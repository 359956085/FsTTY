# 轻量模式

## 使用与边界

- 标题栏叶子按钮为 46×52 点击区，所有状态无矩形背景、边框和阴影，仅改变图标颜色。
- 进入前暂停终端输出，等待同通道 FIFO 屏障和 xterm 写队列排空，再分块提交快照。失败或超时恢复原通道，按序补发缓冲内容。
- 每块原始快照不超过 192 KiB；终端保留最多 10,000 行历史。后台缓存上限为单终端 32 MiB、全部终端 128 MiB；超限折叠到当前画面，旧历史不可恢复。
- 当前画面由 `vt100` 旁路解析。恢复先使用原尺寸，再同步实际 PTY 尺寸；截断时请求 TUI 重绘。
- Shell 钩子令牌只在内存中保留，恢复时不重新注入初始化命令，避免影响正在运行的 Vim 等程序。
- 上传批次和下载由 Rust 接管。窗口关闭后继续运行；同名冲突等待恢复界面后决定覆盖、跳过或取消。结果保留到前端确认。
- CPU、内存统计和网络速率计算由 Rust 按 GUI 连接管理。每轮完成后等待 5 秒再采样，整轮超时 10 秒；轻量期间继续执行，普通模式不会额外启动第二套采样。
- 每连接仅在内存保留最近 10 分钟、最多 121 条样本及最新设备状态。失败留曲线断点，不填零；恢复界面直接读取缓存，不清空历史或重置时间轴。断开、删除、孤立连接清理及退出进程时停止任务并释放缓存；MCP 无头连接不自动采样。
- 正在连接、认证、下载或安装应用更新时不能进入轻量模式。
- 托盘“显示主窗口”恢复界面；GUI 全模式单实例覆盖普通、最小化、最大化和轻量模式，不受轻量开关控制。`--mcp-stdio` 不受 GUI 单实例限制。
- 普通关闭按钮和托盘“退出 FsTTY”均退出进程，取消任务并尝试清理临时文件；网络故障可能使远端清理失败。

仅 `active`、`suppressConfirmation` 和配置版本写入 `lightweight-mode.v1.json`，使用主文件、备份与临时文件提交。位置、尺寸和最大化状态由窗口状态插件保存，不保存可见性。终端快照、目录、文件传输路径和设备统计历史不写入轻量配置或日志。

轻量开关跨进程重启保留。SSH、Vim 未保存内容、传输任务仅保证同一进程内保活，不能抵抗程序退出、崩溃、断电或网络断线。恢复收尾失败时可点击错误条中的“重试完成恢复”。

## GUI 全模式单实例

- 使用固定应用标识 `com.fengshi.fstty`，单实例插件始终最先注册。同一登录会话内只保留一套 GUI、托盘和 MCP HTTP 服务。
- 应用数据目录中的 `.gui-startup.lock` 只用于串行化 GUI 初始化。门闩从 Tauri 构建前持有到 `setup` 成功完成，避免第二个进程在实例通知窗口尚未就绪时继续初始化。最多等待 30 秒；失败则结束本次启动，不绕过门闩。
- 锁文件不保存进程号、会话或凭据，不主动删除。正常返回、初始化失败及进程退出后，由文件句柄关闭释放系统锁；不需要手工删除锁文件。
- 再次启动与托盘点击共用异步唤回入口。普通窗口显示并聚焦，最小化窗口先还原，最大化窗口保持最大化；轻量模式只重建缺失的主窗口，不重建 SSH 或传输任务。
- 连续唤回请求合并处理。轻量快照事务进行中，等待提交或回滚完成后再唤回；提交销毁请求后，还须等待实际 `Destroyed` 事件移除旧窗口，不能复用即将失效的句柄。等待销毁超过 30 秒会结束本次唤回，后续点击可以重试；窗口创建失败不清除轻量状态。
- 退出过程中忽略唤回请求，并等待后台任务清理完成；不会因重复退出事件提前放行。待进程退出后可重新打开。不会自动结束旧版本进程。
- 独立 MCP stdio 进程和 WebView2 子进程不计为第二个 GUI 实例。单实例不要求任务管理器中只有一个系统进程。

## 自动检查

在仓库根目录执行：

```sh
npm ci
npm run verify:all
cargo audit --file src-tauri/Cargo.lock
```

覆盖配置损坏与回滚、错误令牌、超时、部分提交、窗口保存/销毁失败、缓存预算、输出顺序、截断与断线墓碑、恢复竞态、后台传输进度、取消及跨批次冲突。新增启动门闩的跨进程竞争、超时、初始化失败与无析构退出测试，以及窗口状态、唤回合并、事务等待和退出竞态测试。测试使用隔离临时目录和模拟窗口，不依赖真实 SSH 或系统凭据库。

设备统计测试覆盖后台持续采样、唯一任务、整轮超时、失败断点与恢复、时间和数量双重上限、取消和迟到结果；Hook 测试覆盖窗口重建、React 状态提交竞态、重复恢复、多标签隔离与重连后的时间起点。

## Windows 手工验收（尚未执行）

以下不能由模拟通道与 Hook 测试替代。使用专门测试会话和临时文件，不在生产会话中试验。

- [ ] 普通模式点击叶子、取消、确认及“不再提示”；鼠标与键盘状态均符合按钮样式。
- [ ] Vim 存在未保存内容时进入并恢复，检查内容、光标、输入模式，无初始化命令串入。
- [ ] `top`、`watch`、连续滚屏、多标签均正常恢复；截断超过 32 MiB 后 TUI 能重绘。
- [ ] 同时观察任务管理器：进入后主 WebView2 进程消失，Rust 进程与托盘仍存在；记录前后内存。
- [ ] 多标签连接后进入轻量模式数分钟，恢复后 CPU、内存曲线包含后台新增样本；网络速率正常，标签间不串数据。
- [ ] 轻量运行超过 10 分钟再恢复，仅显示最近 10 分钟；反复进入和恢复不重复累计，断开重连后不沿用旧连接历史。
- [ ] 上传批次和下载在后台继续；完成后恢复显示结果；冲突等待恢复，覆盖、跳过、取消各检查一次。
- [ ] 主动取消或断开测试连接，确认任务结果正确；确认本地及远端临时文件清理情况。
- [ ] 改变窗口位置、尺寸和最大化状态，进入并恢复后保持；托盘恢复可反复操作。
- [ ] 在轻量状态退出并重启，只显示托盘；再次启动恢复已有窗口，不产生第二套托盘或 HTTP 端口冲突。
- [ ] 使用新构建快速重复启动：仅一个 GUI 主实例、一套托盘及一个 MCP HTTP 监听服务；已有 SSH、上传下载不受影响。
- [ ] 普通窗口再次启动后聚焦；最小化窗口还原；最大化窗口保持最大化；多个 `--mcp-stdio` 客户端仍可同时运行。
- [ ] 在轻量切换期间快速重复启动或点击托盘，事务结束后只恢复一个主窗口；退出过程中点击不重新显示窗口。

## 依赖依据

- xterm 6.0.0 配套 [`@xterm/addon-serialize 0.13.0`](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0)。该包旧版 peer 元数据仍指向 xterm 5，项目通过 `.npmrc` 保持可重复 `npm ci`；不因此改用 0.14.x。
- [Tauri 单实例插件](https://v2.tauri.app/plugin/single-instance/)放在其他 GUI 插件前注册。
- [窗口状态插件](https://v2.tauri.app/plugin/window-state/)仅保存位置、尺寸和最大化，销毁窗口前显式保存。
