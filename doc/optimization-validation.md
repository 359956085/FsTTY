# FsTTY 优化与交互验收

## 首轮：性能与交互保护

日期：2026-09-29。源码基线：`695a79f`，结果来自本轮工作区修改。

本轮实现 MCP 缓存连接回收、可见设备面板快照轮询、文件面板渲染隔离。设置页及弹窗保持原有加载方式，没有新增懒加载、文件列表虚拟化、安装器改造或依赖集中升级。外部 MCP、Tauri IPC、配置和数据库结构不变。

### 实现边界

- MCP 工具持有内部连接守卫直至调用结束，错误与请求取消也会释放使用计数。最后一个使用者退出后才开始计算 300 秒空闲时间。每个新缓存连接只有一个回收任务，复用会唤醒并重新计时，替换会使旧任务退出。网络操作不持有缓存表锁，回收仅按 MCP 连接 ID 断开。
- `useSessionConnections` 通过内部 `devicePollingRuntimeId` 选择观察对象，仅当会话页可见、右栏展开且活动标签已连接时读取快照。Rust 采样继续运行；恢复时立即读完整历史，有历史时沿用已有画面和加载状态。
- 同一标签的同一连接复用未完成的快照读取，通过轮询代次、请求代次与连接 ID 隔离旧响应。重连可以从新的时间起点开始，慢快照不会阻塞文件请求。
- 文件面板使用 React 默认浅比较和稳定回调。所有文件操作都依赖当前标签及实际使用的函数，保留原组件 key、选择及拖放状态归属；文件、目录、传输和语言变化仍会更新。

## 第二轮：会话表单与更新日志焦点修复

日期：2026-09-30。源码基线：`bd57707`，结果来自本轮工作区修改。

### 实现边界

- 共享 `useDialogFocus` 仅用于会话表单和更新日志，负责首次聚焦、动态排除隐藏/禁用控件、Tab 首尾循环、无可用控件时聚焦容器，以及关闭后的焦点恢复。最新回调和忙碌状态通过 ref 读取，语言及普通重渲染不重置焦点；其他弹窗已接管焦点时不会抢回。
- 会话表单通过标题关联提供名称，打开时聚焦主机。Esc 尊重输入法组合与子控件的 `defaultPrevented`；分组和认证菜单先收起，下一次 Esc 才关闭表单。Esc 与关闭按钮共用忙碌保护，保存/管理凭据期间均不能关闭，保留原有保存、校验和蒙层行为。
- 两个新建入口分别记录实际按钮；右键编辑在菜单卸载前记录会话行，关闭后返回该行。行消失或不可见时使用标签栏新建按钮；目标已卸载则不强行聚焦。
- 更新日志继续使用原有 lazy/Suspense。关于页持有完整焦点生命周期，加载占位和正文注册当前容器；加载中可用关闭按钮、Tab 和 Esc，内容到达时不会先恢复背景焦点，取消后的加载结果不会重开弹窗。
- Windows 检查发现 WebView2 会让滚动正文成为隐式 Tab 停靠点，已允许浏览器从内部焦点自然前进，并为日志正文明确设置可聚焦的命名区域。蒙层的 mousedown 取消默认焦点转移，避免覆盖关闭时恢复的入口焦点。
- 不新增依赖；其他弹窗、终端、轮询、文件面板、公开 MCP/IPC、配置及数据库保持原范围。Workspace 仅透传新建按钮的 ref 和点击事件。

## 第三轮：文件与会话操作的键盘体验

日期：2026-10-03。源码基线：`043ce0b`，结果来自本轮工作区修改。

### 实现边界

- `ContextMenu` 区分 Esc、Tab、选项执行、外部点击和布局变化。首次聚焦可用项，方向键循环，Home/End 到首尾，Enter/空格只执行一次；动态禁用或移除当前选项时修复焦点，普通重渲染保持焦点。全禁用时容器承接键盘。仅处理菜单内事件，并尊重组合输入、229 键码及 `defaultPrevented`。
- Tab/Shift+Tab 先返回原入口，再保留浏览器的默认导航。Esc 返回入口；外部点击交给点击目标。执行选项时在调用操作之前恢复入口，使随后打开的弹窗或编辑器接管焦点，卸载时不额外恢复。
- 文件行、会话行、分组和标签支持菜单键及 Shift+F10。文件与分组列表有可聚焦容器，入口失效或列表为空时仍能继续导航。关闭标签的结果提交后使用当前活动标签，无标签时使用新建按钮；终端激活不会覆盖该次入口恢复。
- 文件新建目录、重命名、删除与分组重命名、删除复用 `useDialogFocus`，补齐标题关联和双向 Tab 循环。编辑首次聚焦输入框，删除确认首次聚焦取消。Esc 与取消共用忙碌保护，操作控制器阻止重复提交；蒙层仍不关闭弹窗。失败保留草稿、错误和弹窗内焦点，批量部分失败保留失败条目供重试。
- `useOperationFocus` 在刷新后的 React 提交阶段查找新条目，不使用延时聚焦。成功新建/重命名定位结果，删除按操作前显示顺序寻找后续首个存活条目、之前最近条目，最后回退列表。请求绑定实例、目录及连接身份；切换、隐藏、卸载、用户转移焦点或另一弹窗接管时失效。分组按同样规则恢复。
- 行内重命名保持失焦提交，Enter/Esc 增加组合输入保护。键盘完成或取消恢复条目，主动点击其他控件保留新焦点；移除原来无保护的 `requestAnimationFrame` 聚焦。重命名使用操作前选区迁移路径，若用户已改选则保留新选择，避免刷新默认选中首行导致额外多选。
- 保留组件 key、记忆化边界和既有操作控制器；没有新增依赖、文件快捷键体系、虚拟列表或全局弹窗框架。接口变化仅为内部焦点目标、菜单关闭原因与文件连接身份，公开 MCP/IPC、配置、数据库、终端生命周期及传输协议保持兼容。

## 切换标签后输出高亮消失修复（2026-10-08）

原生受控 CMD 复现确认：标签重新激活会通过原有布局逻辑再次请求尺寸同步，即使列/行数相同，ConPTY 也会重绘现有屏幕（光标定位、历史行与行尾擦除）。原显示层按编辑操作清除这些行的装饰，且重绘发生在输入阶段，不会重新识别历史输出。因此，仅保留 React/xterm 实例不足以保留补色。

每个本地 host 现在记录实际 PTY 尺寸，对相同尺寸请求不再次调用 ResizePseudoConsole；真实尺寸变化仍同步，成功后更新尺寸记录，不改变 IPC、权限或进程生命周期。高亮层在真实尺寸变化时保留可见的已确认输出候选，使用内部有界双校验值核对逻辑行内容，只有完全一致且无原有样式的行才重新绘制装饰；改写内容不沿用旧色，下一次 execute 通知前结束恢复窗口。校验值不包含在 IPC/轻量快照中，不额外保存文本或记录用户输入；重启、裁剪和卸载继续清理。
