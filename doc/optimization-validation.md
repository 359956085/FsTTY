# 首轮优化与交互验收

日期：2026-09-29。源码基线：`695a79f`，结果来自本轮工作区修改。

本轮实现 MCP 缓存连接回收、可见设备面板快照轮询、文件面板渲染隔离。设置页及弹窗保持原有加载方式，没有新增懒加载、文件列表虚拟化、安装器改造或依赖集中升级。外部 MCP、Tauri IPC、配置和数据库结构不变。

## 实现边界

- MCP 工具持有内部连接守卫直至调用结束，错误与请求取消也会释放使用计数。最后一个使用者退出后才开始计算 300 秒空闲时间。每个新缓存连接只有一个回收任务，复用会唤醒并重新计时，替换会使旧任务退出。网络操作不持有缓存表锁，回收仅按 MCP 连接 ID 断开。
- `useSessionConnections` 通过内部 `devicePollingRuntimeId` 选择观察对象，仅当会话页可见、右栏展开且活动标签已连接时读取快照。Rust 采样继续运行；恢复时立即读完整历史，有历史时沿用已有画面和加载状态。
- 同一标签的同一连接复用未完成的快照读取，通过轮询代次、请求代次与连接 ID 隔离旧响应。重连可以从新的时间起点开始，慢快照不会阻塞文件请求。
- 文件面板使用 React 默认浅比较和稳定回调。所有文件操作都依赖当前标签及实际使用的函数，保留原组件 key、选择及拖放状态归属；文件、目录、传输和语言变化仍会更新。

## Windows 隔离测量

使用本次新建的 Windows Sandbox：Windows 11 build 26100，16 个逻辑处理器，FsTTY 使用 WebView2 `153.0.4234.48`。沙盒内安装 Debug NSIS 验证包，空会话列表、默认设置，没有导入真实连接或凭据。宿主已安装的 FsTTY 未被替换。

普通验证包通过以下命令生成并在沙盒内完成静默安装，退出码为 0：

```powershell
npm run tauri -- build --debug --bundles nsis --config src-tauri/windows/validation.conf.json
```

普通验证包首次启动，从调用启动进程到检测到原生窗口约 **509.9 ms**（50 ms 轮询）。原生窗口出现可能早于网页内容，这个数值不作为界面就绪时间。

随后使用只位于本地 `artifacts/ux-validation-20260929/trace.conf.json` 的诊断配置，为 WebView 设置全新数据目录并通过 `additionalBrowserArgs` 记录 Chromium trace。正式配置和产品源码未加入计时逻辑。环境变量方式在本次管理员兼容环境中未生效，故改用程序配置传参；这一行为与 [WebView2 参数说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags) 一致。

| 测量对象 | 单次测量 |
| --- | ---: |
| 应用进程启动调用 → 首屏内容绘制（FCP） | 1,190.4 ms |
| `http://tauri.localhost/` 导航开始 → FCP | 327.9 ms |
| 新建会话首次点击 → 下一帧 | 48.9 ms |
| 设置页首次点击 → 下一帧 | 54.8 ms |
| 更新日志首次点击 → 下一帧 | 84.9 ms |
| 右栏收起点击 → 下一帧 | 29.9 ms |
| 右栏键盘展开 → 下一帧 | 35.7 ms |

启动采用同一沙盒内的 QPC 单调时钟与 trace 的 FCP 时间戳相减；交互采用 trace 中按操作顺序对应的 `EventTiming` 数据。这里的“下一帧”是浏览器输入响应口径，不包含自动化工具截图和通信耗时，也不等同于全部异步工作结束。口径参考 [Event Timing](https://www.w3.org/TR/event-timing/) 与 [Paint Timing](https://www.w3.org/TR/paint-timing/)。

诊断启动是新进程、新 WebView 缓存目录，未清空系统文件缓存。以上是单次 Debug 虚拟机样本，存在诊断开销，没有发布版或优化前的耗时对照，不能据此宣称加速比例、P95 或所有设备上的响应水平。后续若考虑懒加载，应先在相同的可还原镜像上重复采样，并同时测量首次打开与再次打开。

本地原始材料位于 `artifacts/ux-validation-20260929/`（Git 忽略）：`input/prepare.ps1`、`input/measure.ps1`、两份验证安装包、`output/startup.json`、`output/startup-instrumented.json`、`output/trace-instrumented.json` 和 `output/timing-summary.json`。普通验证安装包 SHA-256：`839554D0D83A3A5E4A7DC3C2DBD644D795B6AA4F14DA8595432C15B29FC7331D`。诊断配置仅供隔离验证，不用于发布。

## 实机交互结果与剩余验收

- 新建会话、设置页、关于页、更新日志首次打开及鼠标关闭正常。
- 切换英语后返回会话页，记忆化的文件面板标题、列名、空状态均正常更新。
- 右栏鼠标收起后，按空格可重新展开，焦点保持在侧栏切换入口。
- 更新日志按 Tab 可进入关闭按钮，Esc 可以关闭；焦点曾移入弹窗后，关闭未恢复入口焦点，随后按空格无法重开。
- 新建会话打开后按 Tab 会进入背景筛选按钮，Esc 未关闭弹窗。`SessionFormDialog.tsx` 与 `UpdateHistoryDialog.tsx` 均未在本轮修改，源码中已有这些焦点管理缺口；本轮保留加载方式，未将弹窗重构混入优化。

完整交互验收仍有缺口：上述原有弹窗焦点行为需要后续修复。多连接真实 SSH 操作、拖放实际传输、长命令与轻量模式下的完整实机会话流程尚未在沙盒测试账号环境补验；对应竞态、连接隔离、选择、传输及保活恢复的自动回归已通过。不能将这些项目标记为实机验收完成。
